## 1. Проект: Веб-сервис бронирования парковочных мест «Park PSU»

## 2. Использованные абстракции Kubernetes

Для запуска и оркестрации приложения в кластере Minikube использованы следующие ключевые абстракции Kubernetes:

### 2.1. Pod (Под)
Минимальная развертываемая единица в Kubernetes. В рамках проекта каждый под содержит один контейнер соответствующего сервиса, изолированное сетевое пространство (IP-адрес внутри кластера) и примонтированные тома (для БД).

### 2.2. Deployment (Развёртывание)
Контроллер, обеспечивающий декларативное описание желаемого состояния подов, автоматическое самовосстановление (self-healing) при падениях и горизонтальное масштабирование:
* **`postgres-deployment`**: развертывание одиночного пода БД со стратегией обновления `Recreate` для предотвращения одновременной записи в один диск с нескольких реплик.
* **`backend-deployment`**: stateless-развертывание серверной части приложения. Поддерживает масштабирование на произвольное количество реплик.
* **`frontend-deployment`**: stateless-развертывание клиентского веб-сервера. Поддерживает масштабирование на произвольное количество реплик.

### 2.3. Service (Сервис)
Сетевая абстракция для маршрутизации трафика и балансировки нагрузки между подами:
* **`postgres` (тип `ClusterIP`):** стабильный внутренний виртуальный IP и DNS-имя внутри кластера (`postgres:5432`). Доступен исключительно внутри кластера, закрыт от прямого доступа извне.
* **`backend` (тип `NodePort`, порт `30080`):** предоставляет доступ к REST API как внутри кластера, так и с хост-машины через порт узла (`NodePort`) или проброс портов `kubectl port-forward`. Балансирует входящие HTTP-запросы методом Round-Robin между всеми готовыми (`Ready`) подами бэкенда.
* **`frontend` (тип `NodePort`, порт `30000`):** предоставляет доступ к пользовательскому веб-интерфейсу Next.js на порту `3000`.

### 2.4. ConfigMap (Конфигурационная карта)
Вынесение нечувствительных конфигурационных параметров за пределы образов (согласно принципам 12-Factor App):
* **`backend-config`**: порт сервера (`PORT=8080`), строка подключения JDBC (`SPRING_DATASOURCE_URL`), разрешенные источники CORS (`CORS_ALLOWED_ORIGINS`), флаг активации шедулера (`SCHEDULING_ENABLED`).
* **`frontend-config`**: порт запуска (`PORT=3000`), публичный адрес API бэкенда (`NEXT_PUBLIC_API_URL`).

### 2.5. Secret (Секреты)
Безопасное хранение конфиденциальных данных:
* **`postgres-secret`**: учетные данные суперпользователя базы данных (`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`).
* **`backend-secret`**: пароль для доступа к БД (`SPRING_DATASOURCE_PASSWORD`), криптографический ключ подписи токенов (`JWT_SECRET`).

### 2.6. PersistentVolumeClaim (Запрос на выделение тома)
* **`postgres-pvc`**: запрос постоянного дискового пространства объемом `1Gi` со стандартным классом хранения (`storageClassName: standard`). Гарантирует сохранение всех таблиц и истории бронирований даже при перезапуске или пересоздании пода базы данных.

### 2.7. Проверки состояния (Health Probes)
Для обеспечения надежности в манифестах настроены:
* **Liveness Probe (проверка жизнеспособности):** перезапускает контейнер при зависании процесса.
  * В БД: вызов утилиты `pg_isready`.
  * В бэкенде: проверка открытия TCP-сокета на порту `8080`.
  * Во фронтенде: HTTP GET запрос на эндпоинт `/`.
* **Readiness Probe (проверка готовности):** исключает под из балансировки трафика сервиса до тех пор, пока он не завершит инициализацию (например, пока Spring Boot выполняет миграции Liquibase).

### 2.8. Ограничения ресурсов (Resource Requests & Limits)
Для предотвращения исчерпания ресурсов ноды (OOM) каждому контейнеру явно заданы запросы (`requests`) и лимиты (`limits`) по CPU и оперативной памяти.

## 3. Схема взаимодействия сервисов приложения

```
+-----------------------------------------------------------------------------------+
|                                  Хост / Клиент                                    |
|                                                                                   |
|    +--------------------------+                   +--------------------------+    |
|    |      Браузер (UI)        |                   |    REST API Клиенты      |    |
|    |  http://localhost:3000   |                   |  http://localhost:8080   |    |
|    +------------+-------------+                   +------------+-------------+    |
+-----------------|----------------------------------------------|------------------+
                  | (port-forward / NodePort 30000)              | (port-forward / NodePort 30080)
                  v                                              v
+-----------------------------------------------------------------------------------+
| Кластер Kubernetes (Minikube)                                                     |
|                                                                                   |
|  +--------------------------------+           +--------------------------------+  |
|  |     Service: frontend          |           |      Service: backend          |  |
|  |     (NodePort: 30000)          |           |      (NodePort: 30080)         |  |
|  +---------------+----------------+           +---------------+----------------+  |
|                  |                                            |                   |
|         Балансировка (Round-Robin)                   Балансировка (Round-Robin)   |
|                  |                                            |                   |
|        +---------+---------+                        +---------+---------+         |
|        |                   |                        |                   |         |
|        v                   v                        v                   v         |
|  +-----------+       +-----------+            +-----------+       +-----------+   |
|  | Pod       |       | Pod       |            | Pod       |       | Pod       |   |
|  | frontend-1|  ...  | frontend-N|            | backend-1 |  ...  | backend-N |   |
|  +-----------+       +-----------+            +-----+-----+       +-----+-----+   |
|                                                     |                   |         |
|                                                     +---------+---------+         |
|                                                               |                   |
|                                                               | JDBC запрос       |
|                                                               | DNS: postgres:5432|
|                                                               v                   |
|                                               +--------------------------------+  |
|                                               |     Service: postgres          |  |
|                                               |     (ClusterIP: 5432)          |  |
|                                               +---------------+----------------+  |
|                                                               |                   |
|                                                               v                   |
|                                               +--------------------------------+  |
|                                               | Pod: postgres-deployment       |  |
|                                               | Container: postgres:16-alpine  |  |
|                                               +---------------+----------------+  |
|                                                               |                   |
|                                                               v VolumeMount       |
|                                               +--------------------------------+  |
|                                               | PVC: postgres-pvc (1Gi)        |  |
|                                               | (Постоянное дисковое хранилище)|  |
|                                               +--------------------------------+  |
+-----------------------------------------------------------------------------------+
```

### Потоки данных и сетевой стек:
1. **Frontend -> Backend:**
   * Статический бандл и SSR-страницы отдаются подами фронтенда.
   * Клиентский код в браузере выполняет асинхронные AJAX/Axios запросы к бэкенду по адресу `http://localhost:8080/api/...` с JWT-токеном в заголовке `Authorization: Bearer <token>`.
2. **Backend -> Database:**
   * При старте бэкенд обращается к базе данных по адресу `jdbc:postgresql://postgres:5432/park_psu`.
   * Встроенный DNS-сервер Kubernetes (CoreDNS) резолвит имя `postgres` во внутренний виртуальный IP-адрес сервиса `postgres` (`ClusterIP`).
   * Сервис направляет TCP-соединение на порт `5432` пода `postgres-deployment`.
   * Liquibase накатывает миграции, создаёт таблицы и начальные тестовые данные парковок.
3. **Хранилище данных:**
   * Каталог `/var/lib/postgresql/data` примонтирован к PersistentVolumeClaim. Все данные физически сохраняются на диске хоста под управлением `storage-provisioner`.

## 4. Сборка и загрузка Docker-образов в Minikube

Сборка образов выполняется с использованием multi-stage Dockerfile в проекте.

### Вариант 1: Использование окружения Docker внутри Minikube
Чтобы собирать образы напрямую в докер-демоне Minikube без необходимости промежуточного пуша в реестр:

* **В Linux / macOS / Git Bash:**
  ```bash
  eval $(minikube docker-env)
  docker build -t sre-backend:latest ./Backend
  docker build -t sre-frontend:latest ./Frontend
  ```

* **В Windows PowerShell:**
  ```powershell
  & minikube -p minikube docker-env --shell powershell | Invoke-Expression
  docker build -t sre-backend:latest ./Backend
  docker build -t sre-frontend:latest ./Frontend
  ```

### Вариант 2: Локальная сборка в Docker Desktop с последующей загрузкой в Minikube
Если образы собраны стандартным Docker демоном хоста:
```bash
# 1. Сборка бэкенда и фронтенда
docker build -t sre-backend:latest ./Backend
docker build -t sre-frontend:latest ./Frontend

# 2. Загрузка образов в кластер Minikube
minikube image load sre-backend:latest
minikube image load sre-frontend:latest
minikube image load postgres:16-alpine

# 3. Проверка наличия образов в кэше Minikube
minikube image list
```

## 5. Состав каталога и файлов манифестов

Манифесты организованы в каталоге `k8s/`:
* `k8s/01-postgres.yaml` — Secret, PersistentVolumeClaim, Deployment (1 реплика, Recreate), ClusterIP Service для СУБД PostgreSQL.
* `k8s/02-backend.yaml` — ConfigMap, Secret, Deployment (с health-чеками и ресурсами), NodePort Service для Spring Boot REST API.
* `k8s/03-frontend.yaml` — ConfigMap, Deployment (с health-чеками и ресурсами), NodePort Service для веб-интерфейса Next.js.
* `k8s/all-in-one.yaml` — Единый объединенный манифест со всеми компонентами для быстрого развёртывания одной командой.
* `start-port-forward.ps1` — Скрипт PowerShell для проброса портов `30000` (frontend) и `30080` (backend) на хост-машину.
