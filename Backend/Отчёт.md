# Отчёт о проекте Park PSU и аудит соответствия методологии The Twelve-Factor App

---

## 1. Доменная область приложения

Приложение **Park PSU** представляет собой систему автоматизации бронирования и мониторинга парковочных мест на территории университетского кампуса (ПГНИУ / PSU).

**Основная цель системы** — обеспечить студентов, преподавателей и сотрудников удобным цифровым сервисом для поиска свободных парковочных мест, их резервирования на определённый временной интервал, отслеживания занятости в режиме реального времени, а также управления собственными активными и завершёнными бронированиями.

### Основные функциональные возможности:
1. **Регистрация и аутентификация пользователей:** безопасная регистрация пользователей с валидацией паролей и выпуском JWT-токенов (access/refresh).
2. **Просмотр доступных парковок:** отображение списка доступных парковочных локаций кампуса с информацией об общем и свободном количестве мест.
3. **Карта парковочных мест:** получение состояния мест конкретной парковки с дифференциацией статуса (`free` — свободно, `occupied` — занято другим пользователем, `mine` — забронировано текущим пользователем).
4. **Бронирование парковочного места:** выбор парковки, номера места, даты, времени начала и длительности парковки с валидацией наложения интервалов.
5. **Автоматическое управление жизненным циклом бронирования:** активация будущих бронирований и автоматическое освобождение мест по истечении времени стоянки.
6. **Отмена бронирования:** досрочное завершение или отмена активной брони пользователем.
7. **Личный кабинет и история:** просмотр текущих активных броней и архива всех совершённых бронирований.

## 2. Стек реализации

Приложение реализовано в виде клиент-серверной архитектуры с разделением на Frontend, Backend и СУБД:

### Бэкенд (текущий репозиторий `park_psu_back`):
* **Язык программирования:** Java 21 (OpenJDK / Eclipse Temurin).
* **Фреймворк:** Spring Boot `3.4.3`.
* **Управление зависимостями и сборка:** Gradle `8.13` (Gradle Wrapper) / `8.5` (в сборщике Docker).
* **Сетевой уровень и API:** Spring Web MVC (REST API over HTTP/1.1), Jackson JSON.
* **Безопасность и авторизация:** Spring Security, JSON Web Token (JJWT `0.11.5`), BCrypt password hashing.
* **Слой данных (ORM):** Spring Data JPA, Hibernate `8.0.0.Final` / Jakarta Persistence API 3.x.
* **Пул соединений:** HikariCP.
* **Миграции базы данных:** Liquibase Core (`db.changelog-master.yaml`).
* **Мониторинг:** Spring Boot Starter Actuator.
* **Вспомогательные библиотеки:** Lombok `1.18.30`, MapStruct `1.5.5.Final`, Jakarta Validation.
* **Контейнеризация:** Docker (Multi-stage build: `gradle:8.5-jdk21` -> `eclipse-temurin:21-jre`).

### Фронтенд (репозиторий `park_psu_web`):
* **Фреймворк:** Next.js `15.2.4` (App Router), React `19.1.0`.
* **Язык:** TypeScript `5.x`.
* **Стилизация и UI:** Tailwind CSS `v4`, Radix UI primitives, Lucide React, Shadcn/ui.
* **HTTP-клиент:** Axios `1.8.4`.
* **PWA:** next-pwa.

### Хранилище данных (СУБД):
* **СУБД:** PostgreSQL.
* **Процедурная логика БД:** PL/pgSQL триггеры и функции (`update_parking_average`, `update_parking_free`, `release_expired_bookings`, `activate_future_booking`), RLS (Row Level Security).

## 3. Основные сущности доменной области

1. **User (`users`)**
   * **Назначение:** учетная запись пользователя в системе.
   * **Поля:**
     * `id` (`int`, PK, autoincrement) — идентификатор пользователя.
     * `email` (`varchar`, Unique, Not Null) — электронная почта (логин).
     * `password` (`varchar`, Not Null) — хэш пароля (BCrypt).
   * **Связи:** один-ко-многим с `BookingLog`, один-ко-многим с `Place`.

2. **Parking (`parkings`)**
   * **Назначение:** физическая территория парковки кампуса.
   * **Поля:**
     * `id` (`int`, PK, autoincrement) — идентификатор парковки.
     * `location` (`varchar`) — текстовое описание или адрес/корпус парковки.
     * `parking_average` (`int`) — общее число мест на парковке.
     * `parking_free` (`int`) — текущее количество свободных мест (вычисляется/обновляется триггерами).
   * **Связи:** один-ко-многим с `Place`, один-ко-многим с `BookingLog`.

3. **Place (`places`)**
   * **Назначение:** конкретное парковочное машино-место на определенной парковке.
   * **Поля:**
     * `place_number` (`int`) — номер места на парковке (составной PK).
     * `parking_id` (`int`, FK -> `parkings.id`) — ссылка на парковку (составной PK).
     * `user_id` (`int`, FK -> `users.id`, Nullable) — идентификатор пользователя, занимающего место в данный момент.
     * `is_occupied` (`boolean`) — флаг занятости места.
     * `booking_time` (`timestamp`) — время начала текущего занятия места.
     * `parking_end_time` (`timestamp`) — время окончания текущего занятия места.
   * **Особенности:** составной первичный ключ (`PlaceId`), содержащий `placeNumber` и `parkingId`.

4. **BookingLog (`booking_logs`)**
   * **Назначение:** журнал истории и расписания всех бронирований (как текущих, так и будущих/прошедших).
   * **Поля:**
     * `id` (`int`, PK, autoincrement) — идентификатор записи журнала.
     * `user_id` (`int`, FK -> `users.id`) — забронировавший пользователь.
     * `parking_id` (`int`, FK -> `parkings.id`) — парковка.
     * `place_number` (`int`) — номер забронированного места.
     * `booked_at` (`timestamp`) — плановое время начала брони.
     * `released_at` (`timestamp`) — фактическое/плановое время освобождения места.
     * `activated` (`boolean`) — признак того, вступила ли бронь в силу в реальном времени.

### 4. Backing Services — сторонние сервисы

**Статус:** ⚠️ Частично соответствует

**Что проверялось:**
* Отношение к сторонним сервисам (СУБД PostgreSQL) как к подключаемым ресурсам.
* Возможность замены сервиса без изменения программного кода.
* Отсутствие жёсткой привязки к конкретным серверам или пользователям БД.

**Что найдено:**
* Доступ к БД осуществляется через интерфейсы Spring Data JPA (`PlaceRepository`, `ParkingRepository`, `UserRepository`, `BookingLogRepository`) и `JdbcTemplate`.
* Подключение к PostgreSQL абстрагировано через JDBC URL.
* Однако в файлах Liquibase-миграций обнаружена жёсткая привязка к конкретному пользователю БД `yumparking`:
  * `create-activate-future-booking-function.yaml:44`: `ALTER FUNCTION activate_future_booking(timestamp) OWNER TO yumparking;`
  * `create-update-parking-average-trigger.yaml:25`: `ALTER FUNCTION update_parking_average() OWNER TO yumparking;`
  * `create-release-expired-bookings-function.yaml:19`: `alter function release_expired_bookings() owner to yumparking;`
  * `create-update-parking-free-trigger.yaml:37`: `ALTER FUNCTION update_parking_average() OWNER TO yumparking;`
* При подключении к чистой локальной базе данных PostgreSQL (где пользователь называется `postgres` или иначе) выполнение этих миграций завершится аварийной ошибкой `role "yumparking" does not exist`.

**Доказательства:**
* `src/main/resources/db/changelog/changeset/create-activate-future-booking-function.yaml:44`

**Соответствие методологии:**
БД является подключаемым ресурсом, но миграции нарушают переносимость между экземплярами БД из-за хардкода роли владельца.

**Антипаттерны:**
* Привязка DDL/DCL скриптов миграции к конкретному пользователю сервера БД.

**Что исправить:**
Удалить инструкции `ALTER FUNCTION ... OWNER TO yumparking;` из changeset файлов Liquibase, чтобы функциями владел текущий пользователь сессии миграции.

**Доказательства:**
* Отсутствие `server.shutdown=graceful` в `src/main/resources/application.properties`.
* `Dockerfile:22`.

**Соответствие методологии:**
Обработка сигналов операционной системы работает за счет корректного ENTRYPOINT и JVM hooks, но без явной активации graceful shutdown запросы могут прерываться с ошибками.

**Антипаттерны:**
* Отсутствие настройки безопасного завершения выполняющихся запросов.

**Что исправить:**
Добавить в `application.properties`:
```properties
server.shutdown=graceful
spring.lifecycle.timeout-per-shutdown-phase=20s
```
